# B站发布稿 — 专栏/动态（配实机演示视频使用最佳）

**标题**：

> 超时空要塞30 原生32:9超宽屏补丁（RPCS3）——3D加宽 + HUD/文字居中，附完整逆向笔记

**正文**：

折腾了两个周末，给《超时空要塞30 连接银河的歌声》（PS3 / BLJS10184）做了一个**原生 32:9（7680×2160）超宽屏补丁**——不是拉伸：3D 投影是真加宽的，HUD、菜单、文字全部原生居中到画面中间，不变形。全程实机验证，已经可以正常通关游玩。

【此处上实机截图/演示视频——驾驶舱 HUD、菜单、加速冲刺】

## 效果

- 3D 画面原生 32:9（主相机投影矩阵 m00 实测减半 0.974→0.487）
- HUD / 菜单 / 文字原生居中，比例正确（CPU 烘焙补丁，不是拉伸也不是挪位）
- 影片是 16:9 预渲染，保持原样（片源如此，无解）
- 已知残留：加速时运动模糊边缘有一条细细的分割线，不影响玩，成因和下一步路线已在仓库里写死

## 使用方法

1. RPCS3 必须用 **v0.0.32-16803**（新版放不了这游戏的影片，坑见 RPCS3 issue #17485）
2. 仓库里拿 `patches/patch.yml` 和 `config_BLJS10184.yml`，放进 rpcs3 对应目录
3. 补丁管理器启用，GPU 勾 **Stretch To Display Area**，**全屏**游玩

仓库（补丁 + 全套逆向工具 + 完整考据文档，英文 README 中文档案）：
https://github.com/ElysionLhant/macross30-uw329

## 给同好看的两句技术梗

- 这游戏的 UI 顶点是 CPU 逐角点现算的，每次绘制都读运行时分辨率——**没有任何常量可搜**，只能把 36 个四边形写出函数全家老小找出来，每个角点改 2 条指令
- 文字渲染的批量循环里，我们要用的那个寄存器被 UV 除数当场撞碎，最后靠给 UV 除数"挪窝"才活下来——寄存器考古学

致谢：3D 加宽的思路学自 [@wagrenier](https://github.com/wagrenier) 的星海（Star Ocean）补丁；本次为与 Kimi（月之暗面 AI）结对逆向开发，实机验证全部通过。
